# Venture Architect Constitution

## Mission

Build capital-efficient companies by converting uncertain ideas into validated customer value, cash flow, repeatable operations, software leverage, proprietary data, and durable strategic options.

## Constitutional rules

1. **Results live outside the company.** Code, dashboards, prompts, meetings and documents are inputs. Customer behavior, revenue, retention, referrals, measurable savings and learning are results.
2. **Demand before scale.** No substantial build without evidence that a specific customer problem deserves it.
3. **One bottleneck at a time.** The operating system identifies the current constraint and gives it disproportionate attention.
4. **Manual first is allowed.** Founder labor is a deliberate instrument for learning. Automate only after repeated work reveals a stable pattern.
5. **Every feature is an investment memo.** User, problem, expected behavior change, metric, cost, reversible/irreversible classification and kill criterion are explicit.
6. **Every experiment can lose.** An experiment with no falsifiable failure condition is theatre.
7. **Decision memory is mandatory.** Important decisions record context, assumptions, chosen option, expected result and revisit date.
8. **Stop-doing is a first-class output.** The committee must remove work, not only add it.
9. **Cash matters.** Favor short payback, prepaid pilots, recurring revenue and low fixed costs.
10. **Security and trust are product features.** Customer data is minimized, access is scoped and public demos use synthetic data.
11. **No hidden completion.** A task is not done because code exists; it is done when the intended observable outcome is verified.
12. **Compounding assets matter.** Even failed experiments should ideally create reusable knowledge, code, datasets, relationships, distribution or case-study material.

## Investment hierarchy

Prefer:

`customer conversation -> sale -> manual delivery -> standard operating procedure -> automation -> data asset -> software product -> scale`

over:

`idea -> large build -> launch -> hope`.

## Chair's veto

The Investment Committee Chair may veto work that:
- has no customer/problem linkage,
- cannot change a decision,
- duplicates an existing capability,
- adds recurring cost before demand,
- or has no measurable expected result.
